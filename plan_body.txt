# Extract a shared seeded-cold-door pipeline for the plan/objective/learn cold doors

## Summary

The seeded cold-door commands repeat one orchestration shape — parse inputs → resolve backend state up front → materialize a scratch/inbox file → support a `--dry-run` `--json` report → `launch_stage` with a seeded prompt — across `plan from`, `plan replan`, `objective plan`, `objective replan`, `objective author --from`, and (already half-shared via `run_factory`) `perk learn docs`/`perk learn code`. Alongside it, three supporting idioms are copy-pasted: the supervisor-surface `fail()` reporter (~10 near-identical copies), the `next(s for s in load_registry().stages if s.id == …)` stage lookup (15 copies), and the `--worktree/--dry-run/--remote/--json/--no-sync/pi_args` Click option block (7 copies).

This plan introduces a shared **seeded-door pipeline** — a new `src/perk/cli/commands/seeded_door.py` module with a `run_seeded_door()` driver, a frozen `SeededLaunch` result dataclass, and a `seeded_door_options()` Click decorator factory — plus two shared primitives (`stage_by_id()` in the registry module, one canonical `fail()` in the CLI error-vocabulary module). The seven doors converge on the pipeline while **per-command policy stays local** in each command's `gather` closure (validation raises, engagement reads, scratch rendering, seed templates, dry-run payload shapes, handoff extras). Behavior is preserved byte-for-byte: the success signal is the existing test suite passing with **zero edits to existing test files** (the byte-pin discipline from `docs/learned/workflow/cold-door-launch.md`).

## Context / research (evidence)

- **The family.** The full repeated shape lives in: `src/perk/cli/commands/plan/from_cmd.py` (`plan_from` + `_plan_from_file`), `src/perk/cli/commands/plan/replan_cmd.py` (`replan`), `src/perk/cli/commands/objective/plan_cmd.py` (`plan_objective`), `src/perk/cli/commands/objective/replan_cmd.py` (`replan_objective`), `src/perk/cli/commands/objective/author_cmd.py` (`_author_from` + `_author_from_file`; the bare `author` arm is a trivial direct launch), and `src/perk/cli/commands/learn/factory_common.py` (`run_factory`, already shared between `docs_cmd.py`/`code_cmd.py` via the frozen `LearnFactoryKind` — the precedent documented in `docs/learned/workflow/plan-factories.md`).
- **Deliberately out of the pipeline:** `skills create`/`skills refine` (different option surface — no `--worktree/--remote/--no-sync`; dry-run branch runs *before* the banner/scaffold; a tracked-file scaffold write on the real path; `skills_fail` deliberately always exits 1 per its docstring), `implement` (no seed prompt; plan-ref selection; `--base`; no `--json` flag), `pr address` / the generic `make_stage_launcher` launchers (thin pass-throughs with no gather), `plan resume` (stage-dynamic relaunch, no seed), and `objective run` (a supervisor, not a launcher). These adopt only the shared primitives.
- **`fail()` copies:** `plan/from_cmd.py`, `plan/replan_cmd.py`, `plan/resume_cmd.py`, `state/prune_cmd.py`, `objective/shared.py`, `doctor/workflow/shared.py`, `workflow/run/shared.py` (plain flavor); `learn/shared.py`, `pr/shared.py` (flavor with an `extra: dict | None` merge); `plan/save_cmd.py` (bakes `"dry_run": False` into every failure payload); `skills/shared.py::skills_fail` (always exits 1 — a documented policy divergence). All plain/extra flavors produce byte-identical JSON when `extra` is `None`/absent, so one superset signature covers them.
- **Test seams verified.** The command tests (`tests/test_from_cmd.py`, `test_replan_cmd.py`, `test_objective_plan_cmd.py`, `test_objective_replan_cmd.py`, `test_objective_author_cmd.py`, `test_learn_factory_common.py`) monkeypatch `launch.launch_stage`, `launch.print_launch_banner_gated`, and the backend module attributes **on their defining modules** and read captured kwargs via `k.get(...)` — so a shared tail that calls `launch.launch_stage(...)` through the imported module object, and that passes explicit `None` for unused optional kwargs, keeps every existing assertion true (the module-object patch rule from `docs/learned/toolchain/python-package-splits.md`).
- **`launch_stage` signature** (`src/perk/run/launch/__init__.py`) already accepts every optional the pipeline threads: `prompt_override`, `handoff_extra`, `binding_trigger`, `run_id_override`, `sync_main` (all defaulted).
- **`fail` never returns:** `click.Context.exit` raises, so a shared exception boundary that calls `fail(...)` then `return`s is behavior-identical to today's inline try/except blocks.
- **Help-text variance** across the shared option block is exactly three phrases: the `--worktree` parenthetical, the `--dry-run` phrasing, and the `<subject> is local-only` clause in `--remote` — hence a parameterized decorator factory rather than a fixed decorator.
- Prior art consulted: `docs/learned/workflow/plan-factories.md` (the parameterized factory-family pattern — frozen config dataclass + thin delegators), `docs/learned/workflow/cold-door-launch.md` (banner-first ordering, narrate-where-the-I/O-happens, byte-exact-pin refactor discipline, `--json` stream testing), `docs/learned/toolchain/python-package-splits.md` (monkeypatch name-resolution).

## Key changes

### 1. `src/perk/substrate/registry.py` — `stage_by_id()`

Add:

```python
def stage_by_id(stage_id: str) -> Stage:
    """The registry stage with ``stage_id`` (raises RegistryError on an unknown id)."""
```

Implementation: iterate `load_registry().stages`; on a miss raise `RegistryError(f"unknown stage id: {stage_id!r}")` (replacing the bare `StopIteration` today's `next(...)` idiom would raise — a non-observable improvement; the registry is bundled and the ids are literals).

Convert **all 15 call sites** of the `next(s for s in load_registry().stages if s.id == …)` idiom and delete the per-module one-line wrappers (`_plan_stage`, `_objective_author_stage`, `_objective_plan_stage`, `_implement_stage`, `_address_stage`, `_save_stage`, `factory_common.plan_stage`, `objective/save_cmd`'s helper, `skills/create_cmd` + `skills/refine_cmd` helpers, `resume_cmd`'s dynamic lookup). The two defensive registration sites (`plan/__init__.py` for the merged `save` + hidden launcher, `learn/__init__.py` for the hidden launcher) call `stage_by_id(...)` inside their existing `try` blocks with the except tuple reduced to `(RegistryError, FileNotFoundError)` (`StopIteration` becomes unreachable).

def fail(

### 3. New `src/perk/cli/commands/seeded_door.py` — the pipeline

The module docstring defines the term: a **seeded cold door** parses inputs, resolves backend state up front (the read-only session cannot be trusted to), materializes untrusted DATA into a scratch file, supports a `--dry-run`/`--json` supervisor report, and ends by `exec`-ing pi via `launch_stage` with a seeded prompt. Three exports:

**(a) `seeded_door_options(*, worktree_help: str, dry_run_help: str, remote_subject: str)`** — a decorator factory applying the five shared trailing options + the `pi_args` argument, in this order: `--worktree` (help = `worktree_help`), `--dry-run` (flag, help = `dry_run_help`), `--remote` (`type=str, default=None, is_flag=False, flag_value=""`, help = `f"Local (default) or a remote runner; {remote_subject} is local-only (cold_remote:false)."`), `--json`/`as_json` (flag, help `"Emit a machine-readable report to stdout."`), `--no-sync`/`no_sync` (flag, help `"Skip the pre-launch fast-forward of the main checkout."`), `@click.argument("pi_args", nargs=-1, type=click.UNPROCESSED)`. Implementation applies the decorators in **reversed** list order inside the returned decorator so Click's `__click_params__` reversal renders `--help` in exactly today's order (leading argument and per-command extras like `--node`/`--from`/`--gather` stay declared locally above the factory). Every converted command passes its **current help strings verbatim** as the factory arguments — `--help` output must be byte-identical.

**(b) `SeededLaunch`** — a frozen dataclass, the contract between a door's local `gather` policy and the shared tail:

```python
@dataclass(frozen=True)
class SeededLaunch:
    seed: str                                # the prompt_override
    launch_note: str                         # stderr note printed under --json on a real launch
    dry_run_label: str                       # the dim header line of the human dry-run report
    dry_run_fields: tuple[str, ...]          # the indented detail line(s)
    dry_run_payload: dict[str, object]       # the FULL --json dry-run payload (policy-owned keys/order)
    dry_run_shows_seed: bool = True          # objective plan and --gather suppress the seed section
    handoff_extra: dict[str, object] | None = None
    binding_trigger: str | None = None
    run_id_override: str | None = None
```

**(c) `run_seeded_door(...)`** — the driver:

```python
def run_seeded_door(
    ctx: click.Context,
    *,
    stage_id: str,
    worktree: str | None,
    dry_run: bool,
    remote: str | None,
    as_json: bool,
    no_sync: bool,
    pi_args: tuple[str, ...],
    backend_errors: tuple[type[Exception], ...],
    gather: Callable[[Path, Config, Stage], SeededLaunch],
) -> None:
```

Behavior (all lifted verbatim from the current commands):

1. `try:` `repo_root = require_repo(ctx)`; `config = require_config(ctx)`; `stage = stage_by_id(stage_id)`; `spec = gather(repo_root, config, stage)`.
2. `except backend_errors as exc:` → `fail(ctx, as_json=as_json, error_type="github_error", message=str(exc))`; `return`. `except UserFacingCliError as exc:` → `fail(ctx, as_json=as_json, error_type=exc.error_type or "invalid_input", message=exc.format_message())`; `return`. (Backend clause first, matching today's ordering.)
3. `if dry_run:` — `--json` → `machine_output(json.dumps(spec.dry_run_payload))` (single payload, no fall-through); human → `user_output(click.style(spec.dry_run_label, dim=True))`, then each `dry_run_fields` line, then — only when `dry_run_shows_seed` — `user_output(click.style("── seed prompt ──", fg="bright_black"))` + `user_output(spec.seed)`; `return`.
4. Real launch: `if as_json: user_output(spec.launch_note)`; then `launch.launch_stage(repo_root=…, config=…, stage=…, worktree=worktree, dry_run=False, remote=remote, pi_args=list(pi_args), prompt_override=spec.seed, handoff_extra=spec.handoff_extra, binding_trigger=spec.binding_trigger, run_id_override=spec.run_id_override, sync_main=not no_sync)`.

Import `from perk.run import launch` and call `launch.launch_stage`/module-attr style so existing monkeypatches keep working. **Everything else stays in the door's `gather` closure**: `require_github` (each door keeps its own placement/gating), id parsing, `launch.resolve_target(stage, remote)` at the door's current point in its sequence, backend/store resolution, `launch.print_launch_banner_gated(...)` (banner-first, before the narrated gather — each door keeps its own gating, e.g. learn's `not gather_only`), the `io_step` narration blocks, validation raises, fail-soft engagement reads, scratch writes, seed rendering, and the `SeededLaunch` construction.

## Assumptions

- **No user-facing behavior change**: all CLI output (stdout JSON payloads, stderr narration, help text, exit codes) is preserved byte-for-byte, so no `docs/user-docs/`, `perk-expert` reference, or `shared/contracts.md` updates are needed (no cross-plane behavior is touched; the registry gains a lookup helper, not a schema change).
- **Boundary widening is benign**: moving the seed render and (for `objective plan`) the post-boundary engagement/seed region inside the pipeline's try block can only convert an impossible-path traceback into a clean `fail` — no caught-exception type is raised in those regions today, and no test pins those paths. Likewise `objective replan`/`objective author --from` keep `backend_errors=(ObjectiveStoreError,)` exactly; an `IssueBackendError` from their GitHub-only OPEN-check reads stays uncaught (today's posture, deliberately preserved).
- **Stage lookup now precedes id parsing** (the pipeline resolves the stage before calling gather, where some doors parsed the id first). Non-observable: the lookup cannot fail user-visibly (bundled registry, literal ids), and `resolve_target` ordering *within* each gather is unchanged.
- **Explicit `None` optionals are safe**: `launch_stage` defaults every optional the pipeline threads, and the test stubs read captured kwargs via `.get(...)`, so always-passing `handoff_extra`/`binding_trigger`/`run_id_override` is indistinguishable from omission.
- **Monkeypatch seams survive**: the pipeline calls `launch.launch_stage` through the `perk.run.launch` module object; banner/backends/engagement calls stay in the command modules — every existing `monkeypatch.setattr(<module>, <name>, …)` keeps binding.
- **`skills create`/`refine`, `implement`, `pr address`, `plan resume`, `objective run` stay off the pipeline** — their divergences (option surface, dry-run-before-banner ordering, scaffold writes, always-exit-1 `skills_fail`, plan-ref selection, supervisor composition) are policy, not drift; they adopt only `stage_by_id`/`fail`. A later plan may revisit the skills doors if their exit-code policy is ever aligned.
- **`learn/shared.py` and `pr/shared.py` are deleted** (they hold only `fail`); their group docstrings' "cross-verb helpers" role is subsumed by `perk.cli.ensure`. `workflow/run/shared.py` and `doctor/workflow/shared.py` survive with their non-`fail` helpers.
- Frozen-dataclass fields hold plain `dict`s (`dry_run_payload`, `handoff_extra`) — mutability inside a frozen container is accepted here, matching `launch_stage`'s own `dict` params.
