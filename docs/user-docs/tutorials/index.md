# Tutorials

**Purpose:** learning-oriented lessons. A tutorial takes a beginner by the hand through a
meaningful, completable project — its job is to get a newcomer started and leave them able
and confident, not to cover everything.

## Authoring rules

- Concrete steps the reader actually performs — a lesson, not a lecture.
- **Every step must work.** Accuracy is gated by a live run-through on a scratch repo before
  a tutorial lands.
- Minimum necessary explanation — link to [explanation/](../explanation/index.md) instead of
  digressing into rationale.
- No options, no alternatives, no digressions: one path, followed to completion.
- This quadrant stays deliberately small — anything beyond the basics belongs in
  [how-to/](../how-to/index.md).

See the [user-docs router](../index.md) for how this quadrant fits the overall system.

## Available tutorials

- [Get started with perk](./get-started.md) — drive one tiny change through perk's complete
  spine (`plan → save → implement → submit → land → learn`) on a throwaway scratch repo.
- [Drive a multi-plan goal with an objective](./drive-an-objective.md) — author an objective
  with a small roadmap and drive its first node from plan to a merged PR, watching perk
  auto-mark the node done and reconcile the roadmap.

This quadrant is deliberately small — exactly two tutorials; everything else is a
[how-to guide](../how-to/index.md).
