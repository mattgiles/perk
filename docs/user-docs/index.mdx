# A deliberate workflow for agent-assisted engineering

<section class="perk-band">

## The workflow

<CoreFlowDiagram />

<div class="perk-diagram-text">
  How does a change move through perk? The spine walks seven stages in order — plan, save,
  implement (shown in-flight as an example), submit, then address only if review asks, then
  land, and finally learn. Review loops guard two stages: every plan is reviewed by a human
  before save, and a submitted PR is reviewed by a human before land — and everywhere a
  human reviews, a built-in agent review wave can optionally assist. Three satellite flows
  feed the spine: gist authoring (plan → save, the same human review loop) seeds objective
  plans and spine plans; objective authoring (plan → save, same loop) emits the spine's
  bounded plans; and the docs/learned cache — perk's durable learned-docs
  store — feeds ambient learned context into all three plan stages. The cache runs two
  curation loops: harvest, which mines it to author one bounded improvement objective, and
  dreaming, which reads the corpus as a whole and authors a reviewed curation objective. The
  spine's learn stage reaches docs/learned only through mediation: /learn captures learnings
  into durable learn issues, and separate perk learn docs plans fold them into the corpus.
</div>

</section>

## How perk fits together

<TwoPlanesDiagram />

<div class="perk-diagram-text">
  Who owns what? The exterior — the perk CLI — scaffolds the repo, manages worktrees, and
  launches Pi; the interior — the Pi session — drives stages, doors, and tools. The planes
  share no in-process code: beyond the launch handoff and the static workflow description
  both planes read, everything they must durably agree on lives in durable state — plans
  and objectives (GitHub issues; on Linear, issues and projects), pull requests, and pushed
  branch commits — with the exterior exchanging plan issues and branches, and the interior
  plan issues and pull requests.
</div>

## Requirements and provenance

perk runs where you already work: it needs `git`, an authenticated `gh`, Node.js ≥ 22, the
`pi` agent harness, the `skills` CLI, and `uv`. See
[Requirements and compatibility](reference/requirements-and-compatibility.md) for version,
model-access, and optional-surface details.

These docs are built from the perk checkout they live in — they describe this code, not a
hosted release. Source: [github.com/mattgiles/perk](https://github.com/mattgiles/perk).
