# The Astro/Starlight docs-site pipeline

The docs site serves the repo's `docs/user-docs/` tree from `docs/site/` — an Astro/Starlight
project whose content collection bridges an **external** source tree (the corpus lives outside
the site directory). Source pointers: `docs/site/astro.config.mjs`, the content config + remark
plugins under `docs/site/src/`, the corpus mirror in `src/perk/learn/docs_scan.py`, and the
guards `tests/test_docs_site_tokens.py` / `tests/test_user_docs_metadata.py`. The binding design
records are `docs/design/docs-site-blueprint.md`, `docs-site-visual-blueprint.md`, and
`docs-site-bridge-spike.md` — point there for the settled decisions; this doc carries the
non-obvious behavioral facts and traps.

## The external-tree bridge (pinned at astro@7.2.1)

- **Build-time validation must be re-derivable from source, not accumulated from renders.** The
  glob loader serves digest-cached rendered entries for unchanged sources, so a per-file
  render-hook audit silently misses *target-only* changes (deleting `b.md` never re-renders the
  `a.md` linking to it). The shipped gate re-sweeps the WHOLE corpus from disk at
  `astro:build:done` — a real `createMarkdownProcessor` parse per file running the same rewrite
  plugin.
- **Remark throws are not a build gate** — the glob loader catches render exceptions and stores
  the entry anyway; precision failures need an integration-level hook throw (`astro:build:done`
  → nonzero exit, confirmed working).
- **Query strings defeat suffix checks:** split the whole `[?#]` suffix off the path part before
  extension/existence tests and reattach verbatim.
- **MDX inherits the unified processor's `remarkPlugins`** — adding top-level
  `markdown.remarkPlugins` alongside double-registers for `.md`; a single
  `markdown.processor: unified({...})` registration is final. Exactly-once was confirmed via a
  two-H1 fixture (double-stripping is otherwise invisible; a reusable fixture design).
- `import.meta.resolve` works inside `astro.config.mjs` (the regex exact-match Vite alias
  shipped with it); workspace resolution is ordinary walk-up into the hoisted root
  `node_modules`. Both pinned renderers set `file.path` on the vfile — a pathless render is a
  legitimate no-op arm.

## Starlight/Astro content facts

- **Autogenerated-nav ordering is NOT directory-local:** a directory's sidebar weight is the
  `Math.min` of the `sidebar.order` values it contains (default `Number.MAX_VALUE`; ties
  alphabetize). Stable top-level order requires globally banded values (a 1000-block per
  section, section `index` = block base, children in steps of 10).
- **The glob loader has a hidden second admission rule:** beyond the pattern
  (`**/[^_]*.{md,mdx}`), tinyglobby defaults `dot: false` — dot-prefixed files AND files under
  dot-prefixed directories are silently unrouted. Any mirror of "what the site routes"
  (`docs_scan._iter_user_docs`, via the `_root_files` kind-dispatcher) must reproduce the dot
  rule, not just the pattern (the convention coupling is recorded in `shared/contracts.md`
  §8.35 — no shared parity fixture; see the residuals).
- **`docsSchema({ extend })` strips unknown frontmatter keys** — declare a custom recorded field
  (e.g. `sidebarGroup`) in the extension schema both to validate it and to keep it;
  unknown-key policing is impossible at the schema layer, so per-directory requiredness/absence
  rules live in the repo guard test; avoid re-defining Starlight-owned nested shapes
  (`sidebar`).
- **Dual-record navigation as a bridge:** structure not expressible by the directory tree (the
  five how-to operator groups) is recorded as validated per-page metadata (a closed-enum group +
  banded order), making the eventual explicit nav config provable against the per-page record
  instead of hand-maintained twice.

## npm-workspace + publish facts

- `"workspaces": ["docs/site"]` makes every root `npm install`/`npm ci` (CI, `just setup`, the
  worktree hook) install the site toolchain (~220 MB — accepted deliberately). Deps hoist to the
  root `node_modules` with `docs/site` symlinked in; the root `.npmrc` `save-exact` governs
  workspace pins; one root lockfile, no site lockfile.
- **Three distinct Node floors — don't conflate:** the root `engines` = the published
  extension's *runtime* claim; the effective *dev install* floor = the strictest dev-dep engines
  enforced by `engine-strict=true`; the workspace declares its own floor mirroring its
  principal dep (verified against the installed package, not registry metadata).
- **Publish isolation is guarded on three independent surfaces:** the npm tarball (forbidden
  prefixes + the `files` allowlist + a pack-output assert), the Python wheel/sdist (a
  member-name scan), and the workspace itself (`private: true`, no runtime `dependencies` key)
  — each layer catches a different failure mode.

## Process patterns

- **Scoped-CI hygiene:** a new file extension (`.mjs`) must be swept into the `[[ci.checks]]`
  glob selectors in the same PR, or future single-extension changes green-skip checks.
- **Uncommitted, fully-reverted simulations as PR evidence** (a frontmatter simulation over the
  corpus, temp fixtures) work — teardown proven by `git status --porcelain`; review wants the
  evidence *on the PR itself*, and an /address pass re-runs items its fixes invalidated.
- A plan's "verified corpus facts" make behavioral edge holes invisible — the render-cache and
  query-string holes were caught only by adversarial PR review; edge cases need adversarial
  reads even when the current corpus can't trigger them.
- An accepted red window between nodes (the corpus collection landing before the frontmatter
  migration) is workable only when loudly disclosed and the later node is barred from wiring the
  CI gate before it clears.

## Residuals

- No committed integration test loads the real Astro config or renders an external-tree page —
  the MDX inheritance, exactly-once plugin application, the components alias, and the build-hook
  nonzero exit are pinned by recorded simulation evidence until the docs-build CI gate node
  lands.
- The build-gate sweep parses `.mdx` best-effort through the markdown parser.
- The site's admission rule and `docs_scan._iter_user_docs` agree by convention only (drift is
  silent).
- The token guard's markdown parsing is coupled to the blueprint's table shapes — a restructure
  fails the parser-sanity asserts loudly; fix the parsers alongside the reconciled blueprint,
  never re-introduce test literals.
- The metadata guard's section-index rule keys on path depth (`parts <= 2`) and needs revisiting
  for nested subsections.
